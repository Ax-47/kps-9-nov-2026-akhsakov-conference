ราคาของ C: เราดูแลหน่วยความจำเอง

char *name = malloc(8);
strcpy(name, "Somchai Jaidee");
free(name);
printf("%s", name);

กิจกรรม: โค้ดนี้มีบั๊กร้ายแรง 2 จุด หาเจอไหม?

~70%

ของช่องโหว่ความปลอดภัยที่ Microsoft แพตช์แต่ละปี มาจากปัญหา memory safety

Matt Miller, Microsoft Security Response Center · BlueHat IL 2019

กิจกรรม 2 นาที: ให้น้องจับคู่กันหาบั๊ก เฉลย: 1) malloc(8) จองไว้แค่ 8 ไบต์ แต่ "Somchai Jaidee" ยาว 14 ตัวอักษร บวกตัวปิดท้าย \0 อีก 1 = 15 ไบต์ เขียนทะลุพื้นที่ที่จองไว้ = buffer overflow 2) free(name) คืนหน่วยความจำไปแล้ว แต่ยังเอาไป printf ต่อ = use-after-free จุดสำคัญ: C ยอมให้ compile ผ่านทั้งสองบั๊ก บางทีรันแล้วยังดูเหมือนปกติด้วย แต่แฮกเกอร์ใช้ช่องแบบนี้เจาะระบบได้ ตัวเลข 70%: Matt Miller จาก Microsoft นำเสนอที่งาน BlueHat IL ปี 2019 ว่าช่วง 12 ปีก่อนหน้านั้น ราว 70% ของช่องโหว่ที่ Microsoft ออกแพตช์แต่ละปีเป็นปัญหา memory safety ปมนี้แหละที่ Java และ Rust จะมาแก้ คนละวิธีกัน
