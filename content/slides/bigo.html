Big-O ในทางปฏิบัติ

ดูขนาด n ก่อน แล้วจะรู้ว่าต้องใช้วิธีไหน

n สูงสุด (ประมาณ)ความซับซ้อนที่ทันตัวอย่างวิธี
≤ 10O(n!)ลองทุกการเรียงสับเปลี่ยน
≤ 20O(2ⁿ)ลองทุกเซตย่อย
≤ 500O(n³)3 ลูปซ้อน, Floyd–Warshall
≤ 5,000O(n²)2 ลูปซ้อน, DP ตาราง 2 มิติ
≤ 1,000,000O(n log n)sort, binary search
≤ 10,000,000O(n)วนลูปรอบเดียว

หลักคร่าว ๆ: คอมทำคำสั่งง่าย ๆ ได้ราว 100 ล้านครั้งต่อวินาที — ใช้ประเมิน ไม่ใช่กฎตายตัว

ทักษะที่คนเก่งทำโดยอัตโนมัติ: อ่านขอบเขตของ n ก่อนอ่านโจทย์ละเอียด วิธีใช้ตาราง: ถ้าโจทย์บอก n ไม่เกิน 100,000 แล้วเราคิดได้วิธีที่วน 2 ลูปซ้อน (n² = 10,000,000,000 ครั้ง) รู้ทันทีว่าไม่ทัน ต้องหาวิธี n log n ตัวเลขในตารางเป็นหลักคร่าว ๆ ที่คนแข่งใช้กัน มาจากการประมาณว่าคอมทำคำสั่งง่าย ๆ ได้ราว 10⁸ ครั้งต่อวินาที ของจริงขึ้นกับเครื่อง ภาษา และความหนักของแต่ละคำสั่ง ลองถามน้อง: ถ้า n = 300,000 ควรใช้วิธีแบบไหน? (n log n) ทักษะนี้เป็น procedural แบบหนึ่ง: ทำโจทย์มากพอ จะเห็นขอบเขต n แล้วนึกออกเองว่าต้องใช้วิธีระดับไหน เหมือน chunking ในกิจกรรมจำตัวเลข
