โปรแกรมเดียวกัน: สร้างตัวละคร → โดนบอสตี 80 → ลองแก้ hp เป็น −70 ตรง ๆ → พิมพ์เลือด

C กับ Java: เกม HSR ฉบับเดียวกัน

C

procedural · ข้อมูลกับฟังก์ชันแยกกัน

#include <stdio.h>
#include <stdlib.h>
typedef struct { int hp; } Ally;
void take_damage(Ally *a, int dmg) {
    a->hp -= dmg;
    if (a->hp < 0) a->hp = 0;
}
int main(void) {
    Ally *a = malloc(sizeof *a);
    a->hp = 100;
    take_damage(a, 80);
    a->hp = -70;  // แก้ตรงได้!
    printf("%d\n", a->hp);
    free(a);      // ต้องคืนเอง
}

ผลลัพธ์: -70 (บั๊กกลับมา)

Java

OOP · ข้อมูลกับเมธอดอยู่ใน class เดียวกัน

class Ally {
    private int hp = 100;
    void takeDamage(int dmg) {
        hp = Math.max(0, hp - dmg);
    }
    int getHp() { return hp; }
}
public class Main {
    public static void main(String[] a) {
        Ally a = new Ally();
        a.takeDamage(80);
        // a.hp = -70; ← compile error
        System.out.println(a.getHp());
    }  // ไม่ต้อง free: GC เก็บให้
}

Class = ข้อมูล + เมธอด

Encapsulation: ซ่อน hp

Method: คำสั่งของ object

Object: ของจริงจากแม่พิมพ์

Abstraction: ไม่ต้องรู้ข้างใน

ผลลัพธ์: 20 (ถูกต้อง)

โปรแกรมเดียวกันทั้งสองฝั่ง: สร้างตัวละครเลือด 100 → โดนบอสตี 80 → มีคนพยายามแก้ hp เป็น −70 ตรง ๆ → พิมพ์เลือดที่เหลือ (สีส้มอ่อนในโค้ดคือจุดที่สองภาษาต่างกัน) วงในโค้ด Java ชี้ concept ของ OOP ให้น้องเห็นของจริง: • กรอบประสีฟ้า (Class) — class Ally คือแม่พิมพ์ที่รวมข้อมูล (hp) กับเมธอด (takeDamage, getHp) ไว้ด้วยกัน ต่างจากฝั่ง C ที่ struct กับฟังก์ชันแยกกัน • Encapsulation — คำว่า private ทำให้ hp ถูกซ่อน แก้ได้ผ่านเมธอดเท่านั้น (ดูบรรทัด compile error ด้านล่างประกอบ) • Method — takeDamage คือคำสั่งที่เป็นของ object เรียกด้วย a.takeDamage(80) ไม่ต้องส่ง a เข้าไปเหมือน C • Object — new Ally() คือการสร้าง “ของจริง” จากแม่พิมพ์ ทีมมีตัวละคร 4 ตัวก็ new 4 ครั้ง ได้ 4 ตัวที่มี hp ของใครของมัน • Abstraction — คนเรียก a.takeDamage(80) ไม่ต้องรู้ว่าข้างในกันเลือดติดลบยังไง รู้แค่ว่า “โดนตีแล้วเรียกอันนี้” (โปรแกรมนี้สั้น เลยมีแค่ Encapsulation กับ Abstraction ส่วน Inheritance กับ Polymorphism ดูในสไลด์ 4 หลักของ OOP) ไล่ความต่าง 4 ข้อ: 1) ข้อมูลกับฟังก์ชัน — C เก็บ hp ไว้ใน struct แต่ฟังก์ชัน take_damage อยู่ข้างนอก ต้องส่ง a เข้าไปเอง / Java เอา hp กับ takeDamage ไว้ใน class Ally เดียวกัน 2) ใครแก้ hp ได้ — C: ใครมี a ก็เขียน a->hp = -70 ได้เลย compile ผ่าน รันได้ ผลลัพธ์คือ -70 บั๊กกลับมา / Java: hp เป็น private บรรทัด a.hp = -70 compile ไม่ผ่านตั้งแต่ก่อนรัน ผลลัพธ์จึงเป็น 20 เสมอ 3) หน่วยความจำ — C: จองเองด้วย malloc และต้องคืนเองด้วย free ลืมคืน = memory leak คืนแล้วยังใช้ = use-after-free (ย้อนไปสไลด์ c-cost) / Java: new แล้วจบ garbage collector ตามเก็บให้ 4) รันบนอะไร — C compile เป็นภาษาเครื่องของแต่ละเครื่องโดยตรง เร็วมาก / Java compile เป็น bytecode แล้วรันบน JVM (Java Virtual Machine) ที่ติดตั้งในแต่ละเครื่อง ความยุติธรรมกับ C (เผื่อน้องสายลึกถาม): C ก็ซ่อนข้อมูลได้ เช่น ประกาศ struct ไว้ในไฟล์ .c แล้วให้ไฟล์อื่นถือแค่ pointer แต่ภาษาไม่ได้บังคับให้ทำแบบนั้น ต้องอาศัยวินัยของคนในทีม ส่วน Java บังคับด้วย compiler ประโยคปิด: ไม่ได้แปลว่า Java ดีกว่า C — C เร็วกว่าและคุมเครื่องได้ละเอียดกว่า แต่ Java แลกความเร็วบางส่วนกับความปลอดภัยและความเป็นระเบียบสำหรับทีมใหญ่ (กลับไปที่ประโยค “ทุกทางแก้มีราคา”)
