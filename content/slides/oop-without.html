ไม่มี OOP · C แบบ procedural

มี OOP · Java

1

Encapsulation

struct Ally { int hp; };
a->hp = -70;
// compile ผ่าน ใครก็แก้ได้

private int hp = 100;
a.hp = -70;
// compile error แตะตรงไม่ได้

2

Abstraction

a->hp += 75;
if (a->hp > 100) a->hp = 100;
// ทุกจุดที่เรียกต้องจำกฎเอง

a.heal(75);
// กฎ 0–100 ซ่อนอยู่ใน heal()

3

Inheritance

struct Food  { char *name; int qty; };
struct Drink { char *name; int qty; };
// field ซ้ำ ต้อง copy ทุกไอเทม

class Food  extends Item {}
class Drink extends Item {}
// name, qty ได้มาจาก Item

4

Polymorphism

switch (it->type) {
  case FOOD: ...; case DRINK: ...;
} // ไอเทมใหม่ = แก้ทุก switch

it.use(me);
// ไอเทมใหม่ = เพิ่ม class เดียว

ไม่มี OOP ก็เขียนได้ — แต่ต้องพึ่งวินัยของคนทั้งทีม

เทียบทีละหลักว่า ถ้าไม่มี OOP (เขียน C แบบ procedural) จะทำแบบเดียวกันยังไง และเจ็บตรงไหน ฝั่งซ้ายคอมเมนต์สีส้มคือปัญหา ฝั่งขวาคอมเมนต์สีฟ้าคือสิ่งที่ OOP ช่วย 1) Encapsulation — C: hp อยู่ใน struct ใครถือ a ก็เขียน a->hp = -70 ได้ compile ผ่าน (บั๊กอมตะ) / Java: private ทำให้บรรทัดเดียวกัน compile ไม่ผ่าน 2) Abstraction — C: ทุกจุดที่จะฮีลต้องเขียนเองว่าบวกแล้วห้ามเกิน 100 ถ้ามี 50 จุดก็ต้องจำ 50 ครั้ง / Java: เรียก a.heal(75) กฎอยู่ข้างในที่เดียว 3) Inheritance — C: ไอเทมทุกชนิดต้องมี name กับ qty (จำนวนในคลังไอเทม) ก็ต้องเขียน field ซ้ำในทุก struct วันหนึ่งอยากเพิ่ม icon ต้องไปเพิ่มทุกตัว / Java: ใส่ไว้ใน Item ครั้งเดียว ลูกทุกตัวได้ไปเอง 4) Polymorphism — C: เวลาจะใช้ไอเทมต้อง switch ตามชนิด และไม่ได้มีแค่ที่เดียว ยังมี switch ตอนวาดไอคอน ตอนเรียงของในคลัง ตอนบันทึกเกม เพิ่มไอเทมชุบตัวละคร 1 ชิ้น = ไล่แก้ทุก switch ถ้าลืมสักที่ก็บั๊ก / Java: เพิ่ม class Revive extends Item ชิ้นเดียว โค้ดเดิมไม่ต้องแตะ ความยุติธรรมกับ C (สำหรับน้องสายลึก): คนเขียน C เก่ง ๆ ก็ทำของพวกนี้ได้ เช่น ซ่อน struct ไว้ในไฟล์ .c และใช้ struct ที่เก็บ function pointer ทำ polymorphism เอง — Linux kernel ที่เขียนด้วย C ก็ใช้วิธีนี้ เช่น struct file_operations ความต่างคือ C ไม่ได้บังคับ ต้องอาศัยวินัยและการตกลงกันในทีม ส่วนภาษา OOP ให้ compiler ช่วยบังคับ ประโยคปิด: ไม่มี OOP ก็เขียนเกมได้ แต่ยิ่งทีมใหญ่ ยิ่งต้องพึ่งวินัยของทุกคน ซึ่งคนลืมได้เสมอ OOP คือการย้ายกฎจาก “ความจำของคน” ไปไว้ใน “ภาษา”
